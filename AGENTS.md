# Инструкции для ИИ-агентов

Прочитайте до первого изменения, в таком порядке:

1. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md): устройство фронтенда, слои, данные, дизайн-система, как
   добавлять карточки, датчики и страницы. Бэкенд описан в репозитории `weather-backend`
   (`docs/ARCHITECTURE.md`): если задание касается данных или API, прочитайте и его.
2. [CONTRIBUTING.md](CONTRIBUTING.md): процесс и правила кода.
3. [README.md](README.md): запуск и команды.

## Запуск обеих частей

```bash
# бэкенд (папка weather-backend): база с тестовыми данными, API :8002, имитатор датчиков
docker compose -f docker-compose.dev.yml --profile live up --build
# фронтенд (эта папка): http://localhost:5173
pnpm install && pnpm dev
```

## Минимум, который нельзя пропускать

* Перед любым «готово»: `pnpm typecheck`, `pnpm lint` (0 ошибок), `pnpm test`, `pnpm build`, и посмотрите
  результат в браузере (светлая и тёмная тема, 375 и 1440 px).
* Слои FSD: `app → pages → widgets → features → entities → shared`, только вниз; `shared` не импортирует
  из верхних слоёв.
* Логика в чистых функциях с тестами рядом (`*.test.ts`, окружение Node); компонент только показывает.
* Тексты только через i18n, новый ключ сразу в `ru`, `uz`, `en`; цвета и пороги в одном месте.
* `null` это «нет показания», не ноль. Любое движение уважает `prefers-reduced-motion`.
* Менеджер пакетов pnpm; новые зависимости только при необходимости; секреты в git не кладём; на боевой
  сервер не ходим; `main` не трогаем напрямую, работаем в ветке и PR.
