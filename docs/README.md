# Карта документации

Папки разделены по тому, **кто читает**. Если вы не уверены, откройте строку со своей ролью.

| Кто вы | Читайте | Папка |
|--------|---------|-------|
| **Новичок: ничего ещё не установлено** | пошаговая инструкция: Git, Docker, pnpm, запуск, pull request | [team/START_HERE.md](team/START_HERE.md) |
| **Участник проекта** (Тулешов, группа №7) | правила работы, зоны, календарь, свои задания | [team/](team/README.md) |
| **ИИ-помощник** участника или владельца | `AGENTS.md` в корне, затем [ARCHITECTURE.md](ARCHITECTURE.md) этого и бэкенд-репозитория, затем документ своей зоны из `team/` | корень и эта папка |
| **Разработчик**, правящий код | [ARCHITECTURE.md](ARCHITECTURE.md), `CONTRIBUTING.md` в корне | эта папка |
| **Пишущий диплом** | план и структура, образец раздела, технический отчёт | [thesis/](thesis/README.md) |
| **Владелец проекта** | проектирование возможностей платформы, сбор данных | [features/](features/SMART_ASSISTANT.md), [data-collection/](data-collection/WINDOW_LOG.md) |

## Что где лежит

```
docs/
  README.md                 эта карта
  ARCHITECTURE.md           устройство фронтенда для разработчиков и ИИ-агентов
  team/                     ДЛЯ УЧАСТНИКОВ
    START_HERE.md             С НЕЁ НАЧИНАТЬ: установка, Git, Docker, pnpm, первый PR
    README.md                 правила, зоны каталогов, календарь, подготовка
    SUMMARY.md                все задания простыми словами (читать первым)
    SPATIAL_VISUALIZATION.md  задания Тулешова: станции, внешние источники, карта
    ANALYTICS.md              задания группы №7: качество данных, статистика, прогноз
  thesis/                   ДЛЯ ДИПЛОМА
    README.md                 структура на 60–80 страниц, кто что пишет, план защиты
    SAMPLE_SECTION.md         образец раздела с формулой, примером и кодом
    PROJECT_REPORT.md         технический отчёт (материал для текста диплома)
  features/                 ПРОЕКТИРОВАНИЕ ВОЗМОЖНОСТЕЙ (владелец)
    SMART_ASSISTANT.md        «умный помощник аудитории»: журнал событий, проветривание, оповещения
  data-collection/          СБОР ДАННЫХ ВРУЧНУЮ
    WINDOW_LOG.md             как вести журнал окон и пар
    window-log-template.csv   шаблон журнала
  internal/                 ИСТОРИЯ ПРОЕКТИРОВАНИЯ (только для ИИ-агентов)
    specs/, plans/            спецификации и планы прошлых работ; участникам читать не нужно
```

Бэкенд (`weather-backend`) устроен так же по смыслу: `docs/ARCHITECTURE.md` для разработчиков и
агентов, `AGENTS.md` в корне; задания и диплом лежат здесь, в репозитории фронтенда.

## Правило, чтобы папки не путались

* Новое задание или правило для участников идёт в `team/`; всё про диплом в `thesis/`; описание
  новой возможности платформы в `features/`; рабочие записи эксперимента в `data-collection/`.
* Архитектурные решения (как устроен код) пишутся в `ARCHITECTURE.md`, а не в `team/`.
* `internal/` не правят: это журнал того, как проектировались прошлые работы.
