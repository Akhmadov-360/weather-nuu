# Задания: пространственная визуализация (участник 2)

Тема: «Web-платформа агрегации и пространственной визуализации экологических показателей
городского воздуха». Твоя зона — **карта**: как данные станций выглядят в пространстве.
Агрегация данных и серверная часть — зона второго участника (Ахмадов А.), вы стыкуетесь через
API (см. «Контракт данных» ниже).

> Статус: **черновик**. Задания T1–T5 можно делать сразу на тестовых данных (фикстурах).
> T6–T7 ждут серверной части (станции и снимок для карты) — об этом сообщим отдельно.

## Как мы работаем

1. Один раз: запусти проект по `README.md` (две команды — бэкенд и фронтенд). Не получилось —
   пиши, а не мучайся: это ошибка в инструкции, её надо исправить.
2. Каждое задание — **отдельная ветка** и **отдельный pull request** (`feature/map-page`,
   `feature/idw`, …). Маленькие PR проверять проще и быстрее.
3. В описании PR своими словами: что сделал, зачем, как проверить. Шаблон подскажет.
4. Перед PR запусти `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` и посмотри
   результат в браузере (консоль без ошибок, светлая и тёмная тема).
5. На ревью я могу задать вопросы по твоему коду: ты должен уметь объяснить каждую строку.
   Это нужно и для защиты диплома.
6. С `main` напрямую работать нельзя, на сервер доступа не требуется и не будет.

### Если пользуешься ИИ-помощником

* Давай ему контекст: `README.md`, текст задания и **конкретные файлы**, с которыми работаешь.
  Он не видит весь проект, поэтому не проси «сделай карту» — проси маленькими шагами.
* Проси **объяснять**, а не только писать код. Код, который ты не понимаешь, на защите не поможет.
* Проверяй результат сам: запусти, посмотри глазами, прогони тесты. ИИ часто пишет код, который
  выглядит правильно, но не работает.
* Обрати внимание на раздел «Важно знать» в `README.md` (версия Tailwind и т. п.).

## Контракт данных (черновик)

Пока сервер не готов, работай с файлами-фикстурами такой формы. Формат может немного
измениться, поэтому данные читай через один модуль (`entities/station`), а не размазывай по
компонентам.

```jsonc
// Станция
{ "id": "room", "name": "Аудитория", "type": "own", "lat": 41.30, "lon": 69.24 }

// Снимок для карты: последние значения всех станций
{
  "generatedAt": "2026-10-10T12:00:00.000Z",
  "items": [
    {
      "stationId": "room",
      "pm25": 18, "pm10": 30, "temp": 24.1, "hum": 38,
      "aqi": 64, "aqiCategory": "moderate",
      "measuredAt": "2026-10-10T11:59:50.000Z"
    }
  ]
}
```

* `aqiCategory`: `good` · `moderate` · `unhealthy_sensitive` · `unhealthy` · `very_unhealthy` · `hazardous`
  (шкала US EPA AQI: 0–50, 51–100, 101–150, 151–200, 201–300, 301+).
* Любое числовое поле может быть `null`: не у каждой станции есть все датчики.
* Координаты в фикстурах **демонстрационные**, настоящие уточним позже.

## T4. Алгоритм интерполяции IDW (ядро твоей работы)

**Цель:** по значениям в нескольких станциях оценить значение в любой точке города.

**Идея:** метод обратных взвешенных расстояний (IDW). Значение в точке `x`:
`v(x) = Σ wᵢ·vᵢ / Σ wᵢ`, где `wᵢ = 1 / dᵢᵖ`, `dᵢ` — расстояние до станции `i`, `p` — степень
(обычно 2). Если точка совпала со станцией — берём её значение.

**Что сделать:** чистая функция без интерфейса `src/shared/lib/geo/idw.ts` (+ расстояние
между координатами) и тесты: одна станция; две станции (середина между ними); совпадение
точки со станцией; станции без данных (`null`) пропускаются; влияние степени `p`; пустой список.

**Готово, когда:** тесты проходят; в `docs/` есть короткое описание алгоритма своими словами
(пойдёт в диплом).

**Что изучишь:** алгоритм пространственной интерполяции, его ограничения (мало точек — это
оценка, а не измерение), тестирование численных функций.

## T5. Тепловая карта

**Цель:** цветовое поле поверх карты, построенное по IDW.

**Что сделать:** слой на `canvas` поверх карты: сетка точек, значение по IDW в каждой, цвет по
шкале AQI; регулятор прозрачности; ограничение дальности (далеко от любой станции поле
бледнеет — там мы ничего не знаем); пересчёт только при движении и масштабе карты, не на
каждый кадр.

**Готово, когда:** на фикстуре видна плавная заливка, карта не тормозит при перемещении.

**Что изучишь:** canvas, производительность отрисовки, компромисс «разрешение сетки ↔ скорость».
Для диплома полезно измерить время построения при разных разрешениях и записать в таблицу.

## T9. Исследовательская часть (для текста диплома)

Это не код, но по сути это половина защиты.

1. **Сравнение с аналогами** (например, IQAir, PurpleAir, OpenAQ): таблица «что умеет каждый /
   чего нет у нас / чем наша платформа отличается», скриншоты, выводы.
2. **Эксперименты с IDW:** как меняется картина при разных значениях степени `p` и разрешении

3. **Ограничения:** честно описать, чего карта не может (мало точек, нет калибровки датчиков).
