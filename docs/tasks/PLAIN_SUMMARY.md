# Что требуется от участников: простыми словами

Короткая версия всех заданий для просмотра и правок. Подробности, критерии «готово» и технические
требования лежат в `README.md`, `SPATIAL_VISUALIZATION.md` и `ANALYTICS.md` этой папки; календарь и
диплом в `docs/thesis/`. Если здесь что-то нужно изменить, правьте этот файл, потом согласуем изменения
с подробными документами.

## Общая картина

Мы делаем **платформу, которая собирает данные о воздухе, проверяет их, показывает на карте и
дашборде, анализирует и подсказывает, что делать**. У датчиков в университете (аудитория и улица)
уже есть живая система. Дальше четыре человека делят работу:

| Кто | Одной фразой |
|-----|--------------|
| **Ахмадов А.** (платформа) | живая система, достоверность данных, интерфейс, новые датчики по университету и отличительная возможность «Когда проветривать» |
| **Тулешов Т.** (пространство) | откуда берутся станции и данные (в том числе из интернета), как считается индекс качества воздуха на сервере, и **карта** с цветной «заливкой» между станциями |
| **Группа №7, часть А** | можно ли данным **доверять** и что они показывают: пропуски, выбросы, суточные закономерности, как часто воздух плохой |
| **Группа №7, часть Б** | что будет **дальше**: прогноз и честная проверка, насколько ему можно верить |

**Для всех:** маленькие pull request-ы (одно задание, одна ветка), свой каталог (чужие не трогаем),
тесты на каждую формулу, тексты на трёх языках. Любую формулу вы должны уметь объяснить словами и на
числовом примере: именно это спросят на защите. По ходу работы каждый записывает «что выбрал и почему»:
из этих записей потом пишется диплом.

## Тулешов Т.

**Что получится в конце:** страница «Карта»: на карте Ташкента маркеры станций (наши и внешние) цвета
качества воздуха, поверх них плавная заливка «как воздух выглядит между станциями» и ползунок времени
«как было вчера». Всё питается от твоего же сервера: таблица станций, внешний источник данных, расчёт индекса.

| Задание | Что это простыми словами | Что сдаёшь в диплом |
|---------|--------------------------|---------------------|
| **B1** | договориться о форме данных (как выглядит «станция» и «снимок для карты») и записать это в схему и образец | таблица полей |
| **B2** | завести в базе станции с координатами и вывести список по адресу `/v1/stations` | схема базы, запись «почему так» |
| **B3** | научить сервер считать индекс качества воздуха так же, как фронтенд | формулы, примеры |
| **B4** | сделать один быстрый запрос «последние значения всех станций» (и «на момент времени») | замеры скорости |
| **B5** | отдавать историю станции для мини-графика | — |
| **B6** | подключить **внешний источник данных** о воздухе (выбрать, сравнить, написать адаптер, чтобы данные из интернета выглядели как наши) | сравнение источников, схема потока данных |
| **T0** | первый маленький PR, чтобы пройти весь путь | — |
| **T1** | страница карты с маркерами | — |
| **T2–T3** | легенда и цвета; карточка станции по клику | — |
| **T4** | **алгоритм IDW**: оценить значение в любой точке по значениям станций (чем ближе станция, тем больше её вес) | формула, пример, графики |
| **T5** | цветная заливка карты по IDW | время построения при разных настройках |
| **T6, T7** | подключить настоящие данные; ползунок времени | — |
| **T8** | переключатель показателей, телефон, языки | — |
| **T9** | сравнение с аналогами; эксперименты с IDW (как меняется картина, где метод ошибается) | таблицы, выводы |

**Математика, которую ты должен знать наизусть:** формула AQI; IDW (веса `1/dᵖ`, влияние `p`, формула
гаверсинусов для расстояния); перекрёстная проверка («убираем по очереди каждую станцию и угадываем её по
остальным»).

## Группа №7, часть А: данные и статистика

**Что получится в конце:** вкладки «Качество данных» и «Статистика» на странице «Аналитика».

| Задание | Что это простыми словами |
|---------|--------------------------|
| **A0** | каркас страницы и форма данных (договориться первыми, чтобы часть Б не ждала) |
| **A1** | показать, сколько данных пришло из ожидаемого, и где были дыры |
| **A2** | автоматически находить подозрительные значения: невозможные, резкие скачки, выбросы, «залипший» датчик. Ничего не удаляем, только помечаем. Проверка: в тестовые данные заранее вставлены известные ошибки, считаем, сколько нашли и сколько ложных тревог |
| **A3** | одно число 0–100 «насколько можно доверять данным» со своей формулой и объяснением весов |
| **A4** | суточные и недельные «портреты» показателей (по часам Ташкента), сравнение «аудитория против улицы» |
| **A5** | как часто воздух плохой: доли времени по категориям, эпизоды плохого воздуха, сколько суток выше нормы ВОЗ |
| **A6** (желательно) | связь пыли с влажностью: действительно ли датчик завышает показания при высокой влажности |

**Математика:** медиана и квартили; фильтр Хампеля (отклонение от скользящей медианы в долях MAD);
доля найденных и ложных срабатываний; корреляции Пирсона и Спирмена; почему корреляция не доказывает причину.

## Группа №7, часть Б: прогноз

**Что получится в конце:** вкладка «Прогноз»: график истории и ожидаемого будущего с коридором
неопределённости и таблицей «какая модель насколько ошибается».

| Задание | Что это простыми словами |
|---------|--------------------------|
| **F0** | договориться о форме ответа; получать из базы ровные почасовые ряды без выдумывания длинных пропусков |
| **F1** | три простейших прогноза: «как сейчас», «как сутки назад», «среднее за последние часы». С ними будем сравнивать всё остальное |
| **F2** | научиться честно измерять качество прогноза: ошибки MAE и RMSE, проверка «как если бы мы прогнозировали раньше». Тест «модель не подглядывает в будущее» |
| **F3** | модель Хольта–Винтерса: учитывает тренд и суточный цикл. Формулы реализуются вручную |
| **F4** | регрессия: прогноз с учётом влажности, температуры и времени суток |
| **F5** | сервер и вкладка: выбирает лучшую модель, показывает коридор, честно говорит «данных мало» |
| **F6** (желательно) | эксперименты: таблица «модель × горизонт × показатель», влияние длины истории, где модель ошибается |

**Математика:** формулы сглаживания (уровень, тренд, сезонность); метод наименьших квадратов;
метрики ошибок; почему простая модель иногда лучше сложной (и что делать, если так получилось).
