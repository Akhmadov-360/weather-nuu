# «Умный помощник аудитории»: отличительная возможность проекта

Принято (владелец, 05.11.2026): отличительная возможность дашборда состоит из трёх связанных звеньев,
которые строятся на данных, уже имеющихся в системе. Документ описывает идею, математику, порядок
работ и ограничения. Расчёты делает платформа (зона владельца), остальные участники дают ей данные и
прогноз.

## Идея

Сейчас похожие сервисы показывают воздух либо на улице, либо в помещении, а решение принимает человек.
У нас есть оба воздуха, внешние станции города и прогноз. Помощник превращает числа в действие:

```
 датчики аудитории ──► [1] Журнал событий ──► события (окно, уборка, пара, отопление)
        │                                           │
        │              уличные данные ───────►      ▼
        └──────────────────────────────────► [2] «Когда проветривать» ──► совет
   внешние станции (B6), прогноз (группа №7)               │
                                                           ▼
                                                  [3] Оповещения (Telegram)
                                                  и карточка на странице «Аудитория»
```

| Звено | Что делает | Польза |
|-------|------------|--------|
| **1. Журнал событий** | сам находит по рядам датчиков проветривание, уборку, начало и конец пар, включение отопления | хозчасти и преподавателям видно, что происходило; даёт разметку для звена 2 |
| **2. Когда проветривать** | сравнивает воздух внутри и снаружи, считает ожидаемый эффект открытого окна, советует: открыть, не открывать, подождать | понятное действие вместо чисел; здоровье, тепло зимой |
| **3. Оповещения** | доставляет совет и прогноз туда, где человек его увидит (Telegram), с защитой от лишних сообщений | информация сама приходит к человеку |

## Звено 1. Журнал событий аудитории

**Что ищем в данных Room** (температура, влажность, давление, пыль PM2.5/PM10, MQ-5, MQ-3):

| Событие | Как проявляется |
|---------|-----------------|
| Проветривание | быстрый спад пыли и влажности и изменение температуры, когда уличный воздух иной |
| Начало пары | рост температуры и влажности, небольшой рост пыли |
| Конец пары | обратный медленный спад |
| Уборка | короткий всплеск пыли и (если спиртовое средство) всплеск MQ-3 |
| Отопление | устойчивый рост температуры без роста влажности и пыли |
| Сбои данных | то, что находит часть А группы №7 (пропуск, выброс, «залипание»): не путать с событием |

**Математика.** Обнаружение точек изменения: по ряду `x_t` с «спокойным» уровнем `μ` (скользящая медиана)
и разбросом `σ` (MAD) накапливается сумма отклонений (метод CUSUM):

```
S_t = max(0, S_{t−1} + (x_t − μ − k·σ)),      сигнал, когда S_t > h·σ          (1)
```

`k` и `h` задают чувствительность. Затем по сочетанию признаков (какие показатели изменились, в каком
направлении, насколько быстро) событие относится к классу по **таблице правил** (понятной и
проверяемой, без «чёрного ящика»). Начало и конец события уточняются по производной ряда.

**Проверка:** по журналу окон и пар ([data-collection/WINDOW_LOG.md](../data-collection/WINDOW_LOG.md)): для
каждого класса события доля найденных (полнота), доля верных из найденного (точность), ошибка по времени
в минутах. Таблица идёт в главу 4. До появления реальной разметки метод проверяется на синтетических
рядах с известными событиями (как `pnpm db:seed --anomalies` для качества данных).

## Звено 2. «Когда проветривать»

### Модель баланса частиц

Аудитория считается одним объёмом. Концентрация пыли внутри `C_in(t)` меняется за счёт притока
уличного воздуха, оседания частиц и внутренних источников:

```
dC_in/dt = a · P · C_out − (a + k) · C_in + S / V                        (2)
```

| Обозначение | Смысл | Единицы |
|-------------|-------|---------|
| `C_in`, `C_out` | PM2.5 внутри и снаружи | мкг/м³ |
| `a` | кратность воздухообмена | 1/ч |
| `P` | доля частиц, проходящих внутрь (0…1) | — |
| `k` | скорость осаждения | 1/ч |
| `S / V` | внутренний источник на единицу объёма (люди, уборка) | мкг/(м³·ч) |

При постоянных `C_out` и `S / V`:

```
C_in(t) = C_eq + (C_0 − C_eq) · e^{−(a + k) · t},    C_eq = (a·P·C_out + S/V) / (a + k)      (3)
```

Внутренняя концентрация экспоненциально стремится к равновесию. При закрытом окне `a` мало (щели), при
открытом велико, поэтому открытое окно меняет концентрацию за минуты.

### Оценка параметров

Вводим скорость выравнивания `λ = a + k` и коэффициент проникновения `η = a·P / (a + k)`. Без внутренних
источников `C_in(t) = η·C_out + (C_0 − η·C_out)·e^{−λt}`.

* На участке после открытия или закрытия окна (источников нет, `C_out` почти постоянна) кривая
  является экспонентой с тремя неизвестными (`C_0`, `η`, `λ`): они находятся **нелинейным методом
  наименьших квадратов** (Гаусса–Ньютона) с доверительным интервалом по остаткам. Если `C_out` постоянна,
  достаточно линейной регрессии `ln|C_in − C_eq|` по времени.
* Отдельно для режимов «окно открыто» (`λ_open`, `η_open`) и «закрыто». Для совета нужны `λ_open` и
  `η_open`: при открытом окне `P ≈ 1`, `a ≫ k`, поэтому `η_open` близка к 1.
* Участки и моменты открытия окон берутся **из звена 1** и сверяются с журналом.
* Раздельно `a` и `k` по пыли найти нельзя; в рекомендации это не требуется.

**Проверка метода оценки:** сгенерировать ряд по формуле (3) с известными `λ`, `η`, добавить шум,
восстановить параметры и сравнить. Так доказывается, что алгоритм работает, до встречи с реальными данными.

### Правило совета

По (3) с оценёнными `λ_open`, `η_open` считаем концентрацию через `T` минут (например, 15), если открыть окно:
`Ĉ_in(T)`.

* **«Открыть»**, если `Ĉ_in(T)` заметно ниже текущей (хотя бы на категорию AQI или на `δ` процентов),
  уличный воздух не хуже «умеренно» и температура снаружи не нарушает комфорт;
* **«Не открывать»**, если снаружи хуже, чем внутри;
* **«Подождать»**, если прогноз (группа №7) обещает улучшение в ближайшие часы.

Гистерезис (разные пороги включения и выключения) и минимальное время удержания предотвращают мигание
совета при шумах.

**Надстройка «цена проветривания зимой»:** потери тепла `Q = ρ·c_p·V·a·ΔT` (плотность воздуха, удельная
теплоёмкость, объём аудитории, кратность воздухообмена при открытом окне, разность температур)
показываются рядом с советом; объём аудитории нужно измерить или оценить.

### Оценка качества

* точность предсказания `Ĉ_in(T)` против реального значения после открытия окна: RMSE и смещение;
* полезность совета: доля советов, после которых воздух стал чище, против правил «всегда открывать» и
  «никогда»;
* чувствительность к ошибке `λ_open` на ±20 %.

### Откуда берётся уличный воздух

* Реальные станции города (задание B6, источник выбирается и согласуется). Они же строят тепловую карту.
* Если на Street появится датчик пыли, он станет основным источником «снаружи».
* Open-Meteo (модель CAMS, шаг сетки около 45 км) годится как **резерв и фон**, а не как точное значение.
* **Датчика CO₂ в системе нет, и внешний API его заменить не может:** переменная `carbon_dioxide` у
  Open-Meteo описывает модельный фон атмосферы, не воздух в аудитории. Первая версия опирается на пыль,
  температуру и влажность, и это записано как ограничение. Если в аудитории появится датчик CO₂,
  появится независимая оценка воздухообмена по спаду CO₂.

## Звено 3. Оповещения

**Канал: Telegram-бот.** Пользователь подписывается (`/start`), выбирает порог (`/threshold`), отписывается
(`/stop`). Типы сообщений:

* «Пора проветрить: снаружи чище» (из звена 2);
* «Через N часов ожидается плохой воздух» (из прогноза группы Б);
* «Воздух в аудитории хуже нормы дольше 15 минут».

**Защита от лишнего:** гистерезис, не чаще одного сообщения заданного типа за N часов, тихие часы
(по умолчанию ночью не беспокоить).

**Данные и приватность:** хранится только идентификатор чата, язык и выбранные пороги; `/stop` удаляет
запись. Токен бота лежит только в `.env` на сервере (репозиторий публичный).

**Что проверить до начала работ (не подтверждено):**
* доступен ли с боевого сервера `api.telegram.org` (университетская сеть может ограничивать);
* как получать сообщения: опрос из самого API (не нужна правка nginx) или webhook через nginx;
* запасной канал на случай блокировки: электронная почта или уведомление на самой странице.

**Миграция:** таблица подписок требует миграции. Правило «миграции только у владельца зоны станций»
сохраняется: миграцию подписок мы делаем **после** слияния модели станций (B2), чтобы номера не
пересеклись.

**Оценка (глава 4):** доля ложных тревог, задержка доставки, доля сообщений, после которых совет был
выполним.

## План работ

Расчёты делаются чистыми функциями с тестами; контракты первыми; модули в зоне владельца:
`modules/events`, `modules/ventilation`, `modules/notifications` (бэкенд); `widgets/ventilation-card`,
`features/event-timeline`, `features/notifications-subscribe` (фронтенд).

| Этап | Что | Результат |
|------|-----|-----------|
| E0 | журнал окон и пар ведётся | сырьё для проверки |
| E1 | чистые функции обнаружения (CUSUM, правила), тесты на синтетических рядах | функции и таблица «найдено / ложное» |
| E2 | проверка на реальных данных и журнале; настройка `k`, `h` | таблица в главу 4 |
| E3 | API `GET /v1/events` и компактная лента событий на странице аудитории | видимый результат |
| V1 | модель (3), оценка `λ`, `η` МНК, тесты на синтетике | таблица «восстановлено / истинно» |
| V2 | правило совета, гистерезис, проверка на событиях | сравнение с «всегда» и «никогда» |
| V3 | API `GET /v1/ventilation/advice` и карточка «Проветривание» | работающая карточка |
| V4 | подключение внешних станций и прогноза, надстройка «цена проветривания» | совет «подождать» |
| N0 | проверка доступа к Telegram, токен, выбор способа получения | решение |
| N1 | бот: подписка, пороги, отписка; таблица подписок после B2 | подписка работает |
| N2 | правила сообщений, гистерезис, тихие часы; режим «сухой запуск» | безопасная отправка |
| N3 | интеграция звеньев 2 и 3; результаты в главу 4 | демонстрация |

Ориентир по календарю: ноябрь — E0, E1, V1, N0; декабрь — E2, E3, V2, V3, N1; январь — V4, N2, N3 и
заморозка функций 31 января.

## Сценарий демонстрации на защите

1. Страница «Аудитория»: идёт пара, пыль растёт, на ленте событий видно «началась пара».
2. Карточка «Проветривание» меняется на «Открыть: снаружи чище» с ожидаемым эффектом.
3. Открывают окно: через минуты пыль падает, лента фиксирует «проветривание»; совет сменился на «Окно
   можно закрыть».
4. В телефоне приходит сообщение, показ подписки и отписки.
Запасной вариант на случай сбоя сети: записанное видео и скриншоты.

## Ограничения (писать честно)

* Модель однозонная: не учитывает расположение окон и людей.
* Нет датчика CO₂: оценка воздухообмена по пыли менее точна.
* Один набор датчиков и мало событий: выводы относятся к этой аудитории.
* Уличные данные чужих станций разного класса; измерения лазерных датчиков не равны эталонным.
* Совет не является медицинской рекомендацией.
